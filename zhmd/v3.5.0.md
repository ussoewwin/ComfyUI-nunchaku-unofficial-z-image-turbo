## 1. 概述

**v3.5.0** 新增 **HSWQ Model Patch Loader** 节点（`HSWQModelPatchLoaderCustom`，显示名 "HSWQ Model Patch Loader (ConvRot INT8 / CPU offload)"），并通过启动补丁恢复了完整的 **SAM3 / SAM3.1 ConvRot INT8** 支持，使 **ComfyUI 标准 SAM3 / SAM3.1 节点** 可以正确加载并运行 ConvRot / TensorWise INT8 检查点（已在 SAM3 与 SAM3.1 上验证检测掩膜正常）。

---

## 2. 新增节点：HSWQ Model Patch Loader（ConvRot INT8 / CPU offload）

移植自 `ComfyUI-NunchakuFluxLoraStacker` 的 `ModelPatchLoaderCustom`（"Model Patch Loader"）。

- **用途**：加载模型补丁（ControlNet、feature projector 等），支持 **CPU offload** 与 **ConvRot INT8**。输出标准 `MODEL_PATCH`，可与标准 apply 节点（`QwenImageDiffsynthControlnet` / `ZImageFunControlnet` / `USOStyleReference`）配合使用。
- **CPU Offload**：`cpu_offload` 开关（BOOLEAN，默认 `True`）可在 CPU 内存中构建模型补丁，不使用 VRAM；配套的运行时补丁（`patches/model_patch_cpu_offload.py`）在补丁以 `load_device=cpu` 加载时让标准 `ZImageControlPatch` 在 CPU 上执行。
- **ConvRot INT8 显存保留**：当检查点带有 `int8_tensorwise` 的 `comfy_quant` 层时，模块图以 `MixedPrecisionOps` 构建，权重在 VRAM 中保持 **INT8**（`TensorWiseINT8Layout`，comfy-kitchen `int8_linear` 在线 ConvRot 旋转）—— 实测 Qwen 121/121、Z-Image 38/38 层 Linear 保持 INT8。
- **Turing 安全计算 dtype**：通过 `comfy.model_management.should_use_bf16()` 自动选择 Ampere+ 使用 BF16、Turing（sm_75）/ 更旧 GPU 使用 FP16（不再硬编码 BF16）。
- **支持的架构**：Qwen Image block-wise ControlNet（`controlnet_blocks.0.y_rms.weight`）、SigLIP multi-feature projector（`feature_embedder.mid_layer_norm.bias`）、Z-Image Fun ControlNet（`control_all_x_embedder.2-1.weight`）。

涉及文件：`nodes/hswq_model_patch_loader.py`（新增）、`patches/model_patch_cpu_offload.py`（新增）、`__init__.py`（注册）、`README.md` + `png/Model Patch Loader.png`（文档）。

## 3. 修复：SAM3 / SAM3.1 ConvRot INT8 支持（恢复）

SAM3 加载器相关工作在 v3.4.8 中被移除（专用节点并非必需 —— 启动补丁方案已能让标准加载器 / 标准 Comfy SAM3 节点处理 ConvRot INT8 检查点）。本版本恢复了 v3.4.9 树中缺失的两层补丁：

### 3.1 comfy_kitchen INT8 非对齐 GEMM 回退（`_patch_comfy_kitchen_int8_gemm_fallback`）

cuBLAS INT8 GEMM 要求 K 与 N 为 4 的倍数。SAM3 的 `boxRPB_embed_x` 输入维度为 2，此前会崩溃（`RuntimeError: INT8 GEMM not supported on this GPU for these dimensions`）。该补丁包装 comfy_kitchen 的 `int8_linear` 及 `TensorWiseINT8Layout` 分发处理器，使非对齐层 **反量化回退到 float 并执行 `F.linear`** 而非崩溃：

- 仅极小的非对齐层在 forward 时以 float 运行（实测仅占 SAM3 INT8 Linear 元素的 **0.0085%**）；所有重型 backbone / transformer 层仍保持 INT8，因此显存缩减效果得以保留。
- `TensorWiseINT8Layout.dequantize` 被替换为数值等价的实现（scale 乘法 + ConvRot Hadamard 逆旋转；实测 `max|d1-d2| = 0.0078`，即 BF16 精度误差）。

### 3.2 SAM3 `process_clip_state_dict` CLIP 键重映射（`_patch_sam3_process_state_dict`）

SAM3 检查点的 CLIP `language_backbone` 以 **q/k/v 预分割形式**存储（无融合 `in_proj_weight`），ComfyUI 标准的 `transformers_convert` 无法重映射这些键（"clip missing"）→ 文本嵌入损坏 → **空/黑掩膜**。该补丁将遗留的 `encoder.*` 键重映射到预期的 CLIP 布局。（SAM3.1 使用融合 `in_proj_weight`，不受此重映射影响。）

### 3.3 SAM3 门控的 `load_state_dict_guess_config` 处理（`_patch_load_state_dict_guess_config_int8`）

仅针对 SAM3 检查点（严格的 `is_sam3` 门控，基于 `detector.` 键 —— 绝不影响 SDXL / Krea2 / Z-Image / FLUX / SD1.5 / SD3 / Wan），标准加载器现在：

- 反量化 `language_backbone`（CLIP）与 Conv2d 键（保持 float），同时**所有 Linear 层保持真 INT8** 驻留 VRAM（`MixedPrecisionOps` / `int8_tensorwise`）。

### 验证

- SAM3.1 ConvRot INT8：检测掩膜正常（已确认）。
- SAM3 ConvRot INT8：检测掩膜正常（已确认）—— 另请注意上游 ComfyUI 的 `scalp=1` 分割头修复（PR #15979 parity）由 `ComfyUI-QwenImageLoraLoader` 提供。
- 完整流水线验证：三个本地检查点的加载 + CLIP 文本嵌入编码均正常。
